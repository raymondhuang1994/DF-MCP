# DF-MCP 0.7：可恢复扫描与本地 Wiki

0.7 在独立的 [DF-MCP 仓库](https://github.com/raymondhuang1994/DF-MCP) 开发，保留 `df-mcp` Skill 名称、`team_drive_` 工具前缀及原有证据读取流程。安装完整 ZIP，不能只替换 SKILL.md。所有业务示例和测试资料均为合成数据。

## 四项功能

| 功能 | 行为 | 价值与限制 |
|---|---|---|
| 1. 可恢复分批扫描 | Windows 网络公盘按经过验证的直接子目录清单提交进度，后续刷新重新核验后续跑 | 已完成资料可以先查；未完成范围持续显示缺口，不能推断删除、全库数量或不存在某资料 |
| 2. 固定本地 Wiki | 持久保存来源摘要、主题、FAQ、冲突页、依赖及维护记录 | 跨聊天复用整理结果，源文件仍只读；Wiki 与索引留在独立本地状态目录 |
| 3. Wiki 导航与原文核验 | Wiki 查询先核对依赖，事实回答再读取相应原文件 | 保留文件 ID、版本、定位和原文引用；引用有效不等于模型解释完全正确 |
| 4. 按依赖增量更新 | 来源变化使相关页面失效并进入重建队列，其他页面保留 | Agent 从当前原文重建受影响页面；不另启无人值守模型服务，不把旧答案当新来源 |

设计借鉴 [Karpathy 的 LLM Wiki 思路](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：保留原始资料，在可持续维护的派生知识层整理联系。DF-MCP 的扫描、权限、版本、源边界和读取覆盖检查仍由运行时代码执行。

## 扫描怎样继续

Windows 网络公盘的同一配置复用扫描周期。正常 `refresh` 或服务运行期间的定期扫描会继续尚未完成的工作；`force=true` 开始新周期，因此不应在每次中断后机械地强制重扫。重连复用已提交状态，不承诺恢复最后一个未提交操作。

每个直接目录的枚举和验证作为一个提交单位；目录身份与变化状态需重新核验。单个目录本身过大、超过条目或时间预算时，它仍是未完成范围，不能把半份目录清单当作完整结果发布。已发布资料仍经过现有的文件访问、版本和读取检查。预算在操作之间检查，不能强制中断正在等待 Windows/SMB 返回的原生调用。

只有全量枚举及重新验证完成后，`coverage.inventory_complete` 才为真。`scan_resume` 报告周期、阶段、完成和待办目录数、恢复情况及最近错误。可用的局部资料不等于全库完成；文件总数、排名、无匹配结论仍需明确总体和完整盘点。未完成盘点不能据此删除未见文件的记录。

本轮断点目录扫描针对 `windows_share`。本地目录与 Microsoft Graph 保留各自扫描流程，复用现有文件解析结果；新增 Wiki 和依赖核验适用于这些来源。Graph 仍不是 delta 同步接口，本轮也没有新增 NFS、原生文件事件监听或网络盘镜像。

## 本地 Wiki 如何工作

安装时仍只有两个来源选项：**A 团队公盘 / 云盘，B 本地磁盘**，可回复字母或直接提供地址。已有配置继续使用原确认的来源及固定本地状态，不为每次聊天新建索引。Wiki 生成内容存于同一受保护状态区域，不能放在网络公盘或云盘同步目录。

当前 Agent 通过 inspect/read 获取证据，整理页面，再调用 Wiki 写入工具。运行时核对引用中的文件、版本、片段定位和原文，并记录依赖。所有页面属于派生、未审核内容；业务批准、解释准确性及遗漏仍需根据原文判断。技术上写入成功不是内容正确性认证。

SQLite 是页面与依赖的权威存储，本地 Markdown 是便于查看的镜像。文件变动、删除、权限撤销或访问失败时，不得绕过 Wiki 工具，直接读取旧 Markdown 来回答。恢复访问后，也应从当前证据重新整理受影响页面。

详细参数和日常工作流见 [Wiki 操作](../skills/df-mcp/references/wiki.md)。Wiki 不包含在通用 ZIP，也不会上传到本仓库。

## 安装与升级

关闭旧连接，保留旧安装和配置备份，安装完整 0.7 包，再用原已确认配置连接。安装目录、来源目录和本地状态目录相互独立。首次运行可能因解析签名变化重新解析；不要删除活动锁或绕过来源身份校验来加快升级。

核对实时 `service_version=0.7.0`，并发现新增 Wiki 工具；只看到新 SKILL.md 或 Hub 的包版本不表示运行时已更新。需要回退时恢复对应旧安装和状态备份，不让旧程序打开新版数据库试探兼容性。

同一用户的多个聊天共用本地服务和状态；不同电脑的同事仍各自有索引和 Wiki。这一版不提供团队集中后台、跨员工权限同步或跨电脑自动共享知识。

## 验收

自动测试应使用隔离的合成资料；真实网络盘、微软租户和业务内容由公司电脑完成以下验收：

1. 实际版本、来源身份和固定本地状态位置正确；原文只读，状态不位于网络盘。
2. 限定扫描预算使盘点中断，确认已完成范围可查询、未完成范围明确；重连后用普通刷新继续，不能把未扫描文件判成已删除。
3. 在续跑前修改目录或来源身份，确认重验或拒绝发生；不能复用失效的目录身份。
4. 对一个真实文件完成 inspect → read，返回实际内容、相同来源版本和可核对定位。
5. 从该证据创建 Wiki 页面，重连后通过 Wiki 工具找到并读取，再回到原文件核对事实。
6. 修改、删除文件或撤销测试来源权限，确认受影响页面不能返回旧内容，并进入维护范围；无关页面继续可用。
7. 从当前可访问原文重建页面；核对乐观版本冲突、未完成扫描、解析缺口和业务冲突均被明确报告。

使用受控测试文件验证删除或权限变化，不修改正式共享盘权限。合成测试通过不代表已在公司 DFS/SMB 或真实 SharePoint 租户验收，也不代表特定秒数或回答准确率。
